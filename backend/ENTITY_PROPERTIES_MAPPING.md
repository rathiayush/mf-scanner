# Entity Properties Mapping - Streamlined Upload Implementation

This document shows how all entity properties are being populated in the new streamlined upload process.

## 1. PortfolioFile Entity

**All Properties:**
- `Id` - Auto-generated by database
- `MutualFundId` - ✅ Set from detected/created mutual fund
- `FileName` - ✅ Set from uploaded file name (with sheet suffix if multi-sheet)
- `FilePath` - ✅ Set to `uploads/{fileName}`
- `FileHash` - ✅ Calculated using SHA256 (includes sheet index if multi-sheet)
- `FileSize` - ✅ Set from `file.Length`
- `ProcessedDate` - ✅ Set to `DateTime.UtcNow` when processing starts
- `Status` - ✅ Set to `Processing` initially, then `Completed` after snapshot creation
- `ErrorMessage` - ✅ Set to `null` initially (updated on error)
- `RecordCount` - ✅ Set to `0` initially, updated to holdings count after processing
- `ReportDate` - ✅ Set from request parameter
- `CreatedDate` - ✅ Set to `DateTime.UtcNow`

**Location:** `StreamlinedUploadService.CreatePortfolioFile()` (Lines 379-392)

---

## 2. PortfolioHolding Entity

**All Properties:**
- `Id` - Auto-generated by database
- `PortfolioFileId` - ✅ Set from created portfolio file ID
- `MutualFundId` - ✅ Set from detected/created mutual fund
- `PortfolioSnapshotId` - ✅ Set from created snapshot ID (snapshot created BEFORE holdings)
- `ISIN` - ✅ Extracted from Excel using `SecurityExtractionHelper.ExtractISINFromRow()`
- `Ticker` - ✅ Extracted from company name using `SecurityExtractionHelper.ExtractTickerFromCompanyName()`
- `SecurityName` - ✅ Extracted from Excel (company name column)
- `Sector` - ✅ Extracted from Excel using `SecurityExtractionHelper.ExtractSector()`
- `Industry` - ✅ Set to empty string (to be populated later)
- `Quantity` - ✅ Extracted from Excel using `SecurityExtractionHelper.ExtractQuantity()`
- `MarketValue` - ✅ Extracted from Excel using `SecurityExtractionHelper.ExtractMarketValue()`
- `Weight` - ✅ Extracted from Excel using `SecurityExtractionHelper.ExtractWeight()`
- `PreviousWeight` - ✅ Set to `null` (calculated during holding changes tracking)
- `AsOfDate` - ✅ Set to `DateTime.UtcNow.Date`
- `CreatedDate` - ✅ Set to `DateTime.UtcNow`

**Location:** 
- Creation: `SecurityExtractionHelper.CreateHolding()` with snapshotId parameter (Lines 474-483)

---

## 3. PortfolioSnapshot Entity

**All Properties:**
- `Id` - Auto-generated by database
- `MutualFundId` - ✅ Set from mutual fund ID
- `SnapshotDate` - ✅ Set from report date parameter
- `TotalValue` - ✅ Initially 0, updated after holdings extraction with sum of all holdings' market values
- `TotalHoldings` - ✅ Initially 0, updated after holdings extraction with count of holdings
- `CreatedDate` - ✅ Set to `DateTime.UtcNow`

**Location:** 
- Initial creation: `StreamlinedUploadService.CreatePortfolioSnapshotPlaceholder()` (Lines 509-534)
- Update with totals: `StreamlinedUploadService.UpdatePortfolioSnapshotTotals()` (Lines 536-569)

**Important:** Snapshot is created BEFORE holdings so that holdings can reference the snapshot ID.

---

## 4. HoldingChange Entity

**All Properties:**
- `Id` - Auto-generated by database
- `MutualFundId` - ✅ Set from snapshot's mutual fund ID
- `ISIN` - ✅ Set from holding ISIN
- `Ticker` - ✅ Set from holding ticker
- `SecurityName` - ✅ Set from holding security name
- `ChangeType` - ✅ Calculated based on comparison (Added/Removed/Increased/Decreased)
- `PreviousQuantity` - ✅ Set from previous snapshot holding (null if Added)
- `NewQuantity` - ✅ Set from current snapshot holding (null if Removed)
- `PreviousWeight` - ✅ Set from previous snapshot holding (null if Added)
- `NewWeight` - ✅ Set from current snapshot holding (null if Removed)
- `PreviousValue` - ✅ Set from previous snapshot holding (null if Added)
- `NewValue` - ✅ Set from current snapshot holding (null if Removed)
- `FromDate` - ✅ Set from previous snapshot date (or current date - 30 days if no previous)
- `ToDate` - ✅ Set from current snapshot date
- `CreatedDate` - ✅ Set to `DateTime.UtcNow`

**Location:** `StreamlinedUploadService.TrackHoldingChanges()` and helper methods (Lines 571-905)

**Logic:**
- Compares current holdings with previous snapshot holdings
- Detects Added, Removed, Increased, and Decreased holdings
- Uses 0.01m tolerance for decimal comparisons to avoid false positives
- Handles duplicate ISINs by using first occurrence
- Automatically recalculates subsequent snapshots if filling data gaps

## Data Cleanup on Re-upload

When re-uploading files for the same mutual fund and date, the following cleanup is performed:

1. **PortfolioHoldings** - Removed for the existing file
2. **PortfolioSnapshots** - Removed for the mutual fund and date
3. **HoldingChanges** - Removed for the mutual fund where FromDate or ToDate matches the report date
4. **PortfolioFile** - Removed

**Location:** `StreamlinedUploadService.CleanExistingDataForReupload()` (Lines 339-359)

---

## Transaction Management

Each file/sheet is processed in its own transaction:
- If any step fails, the entire transaction is rolled back
- No partial data is left in the database
- Other files/sheets can still succeed independently

**Location:** `StreamlinedUploadService.ProcessSingleSheetWithTransaction()` (Lines 172-265)
